   content storage
      The LOCKSS stack's **content storage** is the storage space devoted to the content being preserved by the system. It consists of one or more :term:`content storage areas <content storage area>`. Content storage is one of three kinds of storage needed by the LOCKSS stack, together with :term:`system storage` and :term:`operating storage`.

      Requirements for content storage are outlined in :numref:`Content Storage Prerequisites` (:ref:`Content Storage Prerequisites`). The content storage areas for the LOCKSS stack are configured in :numref:`Content Storage Areas` (:ref:`Content Storage Areas`). Adding, removing, or reordering the content storage areas requires a reindexing step.

   content storage area
      A **content storage area** is an individual directory of :term:`content storage`, as content storage can consist of one or multiple areas.

   log storage area
      The LOCKSS stack's log storage area is devoted to log files generated by the :ref:`Stack Components`. The log storage area is one of the three areas of :term:`operating storage`, together with the :term:`state data storage area` and the :term:`temporary storage area`.

      The log storage area for the LOCKSS stack is configured in :numref:`Log Storage Area` (:ref:`Log Storage Area`).

   K3s
      `K3s <https://k3s.io/>`_ is a lightweight, open source :term:`Kubernetes` distribution by `Rancher <https://www.rancher.com/>`_, a subsidiary of `SUSE <https://www.suse.com/>`_. The LOCKSS Installer sets up K3s on the host system and runs the LOCKSS stack on it as a suite of :term:`containers <container>`.

      K3s is installed in :numref:`Installing K3s` (:ref:`Installing K3s`), after a number of preliminary steps in :numref:`Checking K3s Prerequisites` through :numref:`Configuring CoreDNS for K3s`.

      Important prerequisites for running LOCKSS apply to the :term:`K3s data directory`.

   K3s data directory
      :term:`K3s` downloads containers and stores configuration and other data into a directory known as the **K3s data directory**. The location of the K3s data directory, by default :file:`/var/lib/rancher/k3s`, is configurable in :program:`install-lockss` (:numref:`Installing K3s`: :ref:`Installing K3s`). The K3s data directory is the most sizeable part of the :term:`system storage` needs of the LOCKSS system.

      Important prerequisites for running LOCKSS apply to the :term:`K3s data directory`, as outlined in :numref:`System Storage Prerequisites` (:ref:`System Storage Prerequisites`): :ref:`prerequisites-k3s-nfs`, :ref:`prerequisites-k3s-xfs`.

   Kubernetes
      `Kubernetes <https://kubernetes.io/>`_ is an open source system for managing :term:`containerized <container>` software applications, governed by the `Cloud Native Computing Foundation <https://www.cncf.io/>`_, a project of the `Linux Foundation <https://www.linuxfoundation.org/>`_. The LOCKSS Installer installs and uses the :term:`K3s` Kubernetes distribution to configure and deploy the LOCKSS stack.

   operating storage
      The LOCKSS stack's **operating storage** is the storage space devoted to its internal operating needs, such as database data, state files, log files, temporary files, etc. Operating storage is one of three kinds of storage needed by the LOCKSS stack, together with :term:`system storage` and :term:`content storage`.

      Operating storage consists of the :term:`state data storage area`, the :term:`log storage area`, and the :term:`temporary storage area`. All three can be set to the same actual directory.

      Requirements for system storage are outlined in :numref:`Operating Storage Prerequisites` (:ref:`Operating Storage Prerequisites`).

   state data storage area
      The LOCKSS stack's **state data storage area** is devoted to database files, state files, and similar persistent data needed as part of normal operation. The state data storage area is one of the three areas of :term:`operating storage`, together with the :term:`log storage area` and the :term:`temporary storage area`.

      The state data storage area for the LOCKSS stack is configured in :numref:`State Data Storage Area` (:ref:`State Data Storage Area`).

   system storage
      The LOCKSS stack's **system storage** is the storage space needed for installed software, downloaded containers, data generated by :term:`K3s`, etc. System storage is one of three kinds of storage needed by the LOCKSS stack, together with :term:`operating storage` and :term:`content storage`.

      Requirements for system storage are outlined in :numref:`System Storage Prerequisites` (:ref:`System Storage Prerequisites`).

      The most sizeable part of the system storage needs of the LOCKSS system is the :term:`K3s data directory`, which has its own particular requirements.

   temporary storage area
      The LOCKSS stack's **temporary storage area** is devoted to temporary files, staging areas for unpacking compressed files or off-heap data processing, etc. The temporary storage area is one of the three areas of :term:`operating storage`, together with the :term:`state data storage area` and the :term:`log storage area`.
